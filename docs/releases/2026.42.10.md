## Upgrade notes

Moves every Unique image and the release-locked Conduct charts (`sbx-gateway`, `sbx-templates`
and its Fargate variant `sbx-templates-fargate`) from `2026.40.4` to `2026.42.10`. The generic
`backend-service` (10.5.1), `web-app` (5.3.0) and `ai-service` (3.0.0) charts are unchanged.

### Conduct: upgrade the sandbox controller first

`agent-sandbox-controller` moves from chart `0.4.6-rc.1` to `1.0.1`, the version every fleet
tenant runs. Since 2026.40, `sbx-templates` emits `extensions.agents.x-k8s.io/v1beta1` and refuses
to render without that API, and assistants-core claims sandboxes through the 1.0.x SDK at the
same version, while `0.4.6-rc.1` serves its CRDs only at `v1alpha1`. This closes the controller
check the 2026.40.4 notes left open. Both templates (peer pods and Fargate) render against the
1.0.1 CRDs with no pruned fields.

A fresh cluster needs nothing more. On a cluster that already has the `v1alpha1` CRDs, the new
ones will not apply over `status.storedVersions: [v1alpha1]`. Follow the fleet's procedure:

1. Delete the old CRDs. This also deletes every Sandbox, SandboxClaim, SandboxTemplate and
   SandboxWarmPool:
   `kubectl delete crd sandboxes.agents.x-k8s.io sandboxclaims.extensions.agents.x-k8s.io sandboxtemplates.extensions.agents.x-k8s.io sandboxwarmpools.extensions.agents.x-k8s.io`
2. Sync `agent-sandbox-controller`.
3. Sync `sbx-templates` and `sbx-templates-fargate`.
4. Restart KEDA, whose cached API discovery otherwise leaves the warm-pool ScaledObject broken:
   `kubectl -n unique rollout restart deployment keda-operator`
5. Sync `assistants-core`.

Two configuration changes ship alongside:

- **Router NetworkPolicy.** The overlay now passes bare labels, the form the chart expects.
- **`sbx-gateway` MITM CA.** Argo CD cannot run the chart's `helm lookup`, so it now ignores the
  CA Secret's data and respects that on sync, as on every fleet cluster. The CA stays stable
  across syncs; rotate it by deleting the Secret.

### Configuration

**No new required instance values.** Every setting the services gained in this window is optional
or defaulted, and no key this repository sets was renamed. `ingestion-worker` gained
`SCOPE_MANAGEMENT_URL`, but only Microsoft Purview (MIP) decryption needs it.

| Where | Change | Effect |
|---|---|---|
| `defaults/backend-services/client-insights-exporter.yaml` | `DATA_SOURCE_URLS` adds `http://backend-service-ingestion.unique.svc/insights` | From 2026.42.0, ingestion serves per-company scope counts with company names. These ship to `CLIENT_INSIGHT_SERVER_URL` with the other sources. The fleet sets this by default. The exporter skips a source that fails, so an environment still on an older release loses only this one |
| `sbx/value-overlays/backend-services/_all.yaml`, `web-apps/_all.yaml`, `web-apps/chat.yaml` | Removed `FEATURE_FLAG_ENABLE_HTML_RENDERING_UN_15131`, `FEATURE_FLAG_ENABLE_NEW_ANSWER_FORMATTING_UN_14392`, `FEATURE_FLAG_ENABLE_NEW_ANSWERS_UI_UN_14411`, `FEATURE_FLAG_NEW_TRANSLATION_UI_UN_7233` | No code reads them at 2026.42.10. The first two became unconditional in this release (UN-16908); the other two were already unused. All were `"true"`, so nothing changes |

Behaviour changes that need no configuration here:

- **New Knowledge Base interface by default.** The `FEATURE_FLAG_ENABLE_NEW_KB_UI_UN_17151`
  registry default is now `true`. Registry flags override env flags in the web apps, so
  knowledge-upload switches over on upgrade. To keep the old interface, set the flag to `"false"`
  in `sbx/value-overlays/backend-services/_all.yaml`, which configuration-backend reads. The new
  empty-folder view still has the "Upload Files" button the KB smoke test drives (checked against
  source, not yet run).
- **node-chat's OpenAI and Anthropic proxies forward only inference routes.** Other paths, such as
  `/v1/files` or `/v1/assistants`, now return 403. To allow more, set
  `OPENAI_PROXY_EXTRA_ALLOWED_ROUTES` / `ANTHROPIC_PROXY_EXTRA_ALLOWED_ROUTES`. An invalid value
  stops chat from starting.
- **The ingestion dead-letter queue drains continuously** into the ingestion error analytics. A
  depth near 0 is normal; a sustained depth means the consumer or the database is down.
- **Agent Benchmarking** (`benchmarking`) joins the release as a separate app, off by default in
  the fleet. It is not deployed here.

Not adopted from the fleet defaults:

- **`WEBSOCKET_AUTH_MODE: ticket`** on the four web apps. Ticket mode fails closed. It needs the
  `unique-jwt-auth` plugin minting and consuming tickets on every WebSocket route, backed by Redis
  database 7. This repository's plugin accepts `?token=` only, so the web apps stay on the default
  `token`. Follow the monorepo's `infrastructure/websocket-auth.md` before switching.
- **The remaining `internalServices` entries** (chat-task-scheduler and unique-api on configuration
  and scope-management, the exporter on ingestion). In the fleet's per-service charts these render
  only network-policy allow rules. The generic charts here take none.

### Conduct charts

- **`sbx-gateway`:** `routes.paths.default.blockList` paths are now blocked on public routes
  without JWT. This repository renders no gateway routes, so nothing changes. With this overlay,
  the rendered output differs only in version labels. Egress logs no longer contain query strings.
- **`sbx-gateway` PDB override:** checked against the new chart, as the 2026.40.4 notes asked. The chart still
  defaults `pdb.minAvailable: 1` and rejects both fields set. The overlay's `null` removes it and
  renders `maxUnavailable: 1`. At the default two replicas that is the same budget, and stricter
  once the HPA scales out.
- **`sbx-templates`:** only the image tag and digest change since 2026.40.4.
