## Upgrade notes

Moves every Unique image and the release-locked Conduct charts (`assistants-core`,
`sbx-gateway`, `sbx-templates` and its Fargate variant `sbx-templates-fargate`) from
`2026.46.0` to `2026.46.1`, a single upstream patch. The generic `backend-service` (10.5.1)
and `web-app` (5.3.0) charts are unchanged.

**Take this release rather than `2026.46.0`.** It carries upstream security updates, and it
repairs the deployment: at `2026.46.0` a Conduct sandbox could not complete a turn. Chat,
Knowledge Base, spaces and the public API were unaffected. Everything below is already applied
in this repository — adopting the tag is enough, there is nothing to do by hand.

### What the upstream patch carries

`2026.46.1` is a patch on the `2026.46` line. It brings Node.js security updates, and fixes to
activity-record boot behaviour, web-search environment validation, error and failed-crawl
logging, and the Cost Management dashboard. Patch releases do not get their own page on
docs.unique.ai; the `2026.46` release notes linked above cover the line.

### What this release repairs

| Area | At `2026.46.0` | Now |
|---|---|---|
| Sandbox scheduling | sandbox pods could land on nodes without the runtime shim | pinned to the nodes that carry it |
| Warm pool | sized below what a serial claim needs | room for three warm sandboxes |
| Generated files | the upload a sandbox makes was refused by the egress policy | allowed, to that one path and method, under injected identity |
| Model access | every Conduct turn ended in about three seconds | the proxy filters the beta values the model host rejects |

### Configuration

**No new required instance values.** Two optional settings are added by this repository and
documented here because they are operator-facing.

| Where | Change | Effect |
|---|---|---|
| `value-overlays/conduct/sbx-templates.yaml` | `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS`, `FORCE_PROMPT_CACHING_5M` | Narrow what the sandbox agent advertises to the model host. Harmless where the host accepts the full set |
| `value-overlays/litellm/litellm.yaml` | `LITELLM_LOCAL_ANTHROPIC_BETA_HEADERS: "True"` | Pins the proxy's beta-header filter table to the one shipped in its image |

### The model proxy moves with this release

`litellm` goes from `v1.81.3` to `v1.81.14`. The older build forwarded the client's
`anthropic-beta` header verbatim, so a single value the model host did not accept failed the
whole request. The newer build filters those values per provider.

That filter table is **pinned to the image** by the setting above. Left unset, the proxy fetches
it from its upstream default branch at start-up, which makes the active model features depend on
when a pod last restarted. Operators who prefer the upstream table can remove the setting.

### The benchmarking model alias still applies

As at `2026.46.0`, chat does not start unless the proxy serves a model named
`AZURE_GPT_4o_2024_1120`. The `gpt-4o-2024-11-20` entry in `value-overlays/litellm/litellm.yaml`
therefore stays. Do not remove it as part of this upgrade.

### Validation

This release is cut only once the browser and API smoke suites pass in full against a cluster
running it, the Conduct checks included: code executes in a sandbox and its output returns, the
workspace survives across turns, and a generated file is stored and linked in the answer.
